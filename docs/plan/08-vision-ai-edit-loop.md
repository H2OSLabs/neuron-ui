# AI 编辑闭环 — 产品愿景

> 本文档只描述产品想法本身，不涉及任何实现方式。

---

## 核心想法

用户在一个可视化界面（App-UI）中操作自己的页面或组件，通过 Chat 或点击编辑按钮，进入一个可视化的属性编辑界面，完成编辑后，系统将这次编辑的完整内容整理成一份结构化数据（Template），交给 AI，由 AI 将变更写回代码并创建 PR，同时页面实时热加载反映最新状态。

---

## 操作对象

用户操作的对象可以是：

- **单个组件** — 页面中某一个具体的 UI 组件
- **整个页面** — 对整个页面的布局、内容、结构进行调整

---

## 流程描述

### 第一步：在 App-UI 中发起编辑

用户在 App-UI（可视化编辑界面）中：
- 选中想要修改的组件或页面
- 通过 Chat 输入自然语言描述想要的变化，或者直接点击"编辑"按钮

### 第二步：进入可视化属性编辑界面（for-component）

点击编辑后，用户进入一个可视化的属性编辑界面。这个界面展示该组件或页面的所有可编辑属性，用户在这里用可视化的方式（而不是写代码）完成修改。

界面中还提供组件搜索能力，用户可以浏览和查找可用的组件。

### 第三步：生成 Template

用户完成编辑并提交后，系统将这次编辑的所有相关内容打包成一份完整的数据（Template）。

Template 包含的内容不仅限于：
- 组件的代码位置
- 编辑前后的变化
- CSS 样式
- 静态资源（assets）
- 以及其他与这次编辑相关的完整上下文

### 第四步：AI 理解并生成变更

Template 作为 Prompt 交给 AI（Claude Code）。

Prompt 的格式可以是结构化的 JSON，类似页面 Schema 的格式，目的是让 AI 能够准确理解这次编辑的意图，并正确地将变更写入代码。

### 第五步：创建 PR

AI 完成代码修改后，自动创建一个 PR，变更通过 PR 合并回主分支。

### 第六步：热加载（Hot-load）

编辑结果通过热加载实时反映在 App-UI 的画布中，用户无需手动刷新即可看到最新状态。

---

## 附：Git 操作

整个流程中，代码的变更管理通过 git 完成：git diff、commit、创建新分支、新建 PR。

---

## 系统全貌示意

```
App-UI（可视化编辑界面）
    │
    ├── Chat（自然语言描述修改意图）
    │       └──► AI 理解布局意图 ──► 页面实时更新
    │
    └── 点击编辑
            │
            ▼
    for-component（可视化属性编辑界面）
    - 展示所有可编辑属性
    - 支持搜索和浏览组件
    - 用户完成可视化修改
            │
            ▼
    Template（完整编辑上下文数据）
    - 组件代码位置
    - 编辑前后变化
    - CSS、assets 等
            │
            ▼
    AI（Claude Code）
    - 读取 Template 作为 Prompt
    - 将变更写入代码
            │
            ▼
    PR（代码变更提交审查）
            │
    ┌───────┴────────┐
    ▼                ▼
合并到主分支      Hot-load
                （画布实时更新）
```
